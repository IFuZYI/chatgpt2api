# 单实例部署，状态留在本地文件

号池、图片任务、可编辑文件任务、调用日志的状态全部是进程内内存 + 本地文件（`data/`），没有外部协调点。这意味着同一个 `data/` 目录只能被一个进程写：跑三个副本会让 `accounts.json` 互相覆盖、`image_tasks.json` 的读-改-写互相吞掉任务、`logs.jsonl` 交错成坏行。这不是可以通过加锁解决的问题——锁只在进程内有效。

决定：明确只支持单实例，多副本部署不受支持。需要水平扩展时的路径是把号池搬到外部有事务语义的存储（postgres 后端已经是这个方向），但即使切到 postgres，`image_tasks.json` 与 `logs.jsonl` 仍然是本地文件，所以那也只是一半的答案。

## Consequences

- 反代层不要对同一 `data/` 目录做多实例负载均衡；要么单副本，要么每个副本独立 `data/`。
- 备份任务、账号 watcher、图片清理定时器都假定自己是唯一执行者，不做分布式选主。
- 这个约束在代码里看不见（没有注释会告诉你别跑两个），所以写在这里。
- 若将来要支持多实例，`StorageBackend` 接口已经是唯一收口，扩展点在那里；但 `logs.jsonl` / `image_tasks.json` / `editable_file_tasks.json` / `image_tags.json` 需要先各自找到替代。
