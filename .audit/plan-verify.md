## 检测维度（7 条逻辑链 + 1 条横切）
1. **请求入口链**：路由注册 → 鉴权 → 参数解析 → 校验 → 错误信封
2. **号池链**：账号导入 → 刷新 → 槽位获取 → 记账 → 限流恢复 → 删除
3. **文本生成链**：chat/responses/messages → 上游 SSE → 增量解析 → chunk 输出 → 缓存
4. **图片生成链**：模型分流 → mask 合成 → 槽位 → prepare → generate → 轮询 → 下载 → 落盘 → 记账
5. **持久化链**：config 读写 → 四后端 → 原子写 → 关闭时刷盘 → 备份归档
6. **后台任务链**：watcher 周期 → 清理调度 → 任务队列 → 关闭语义
7. **前端契约链**：每个 API 的字段形状 → 错误解析 → 轮询协议
8. **横切**：死代码 / 未接线配置 / 测试盲区 / 并发安全 / 资源泄漏

## 全局约束
- 每个发现必须有 file:line 证据
- 区分「真缺陷」/「已声明偏离」/「合理改进」
- 不臆测，读代码
- 不修改代码（本轮只检测）

## 验证标准
1. `go build ./...` / `CGO_ENABLED=0 go build ./...` 通过
2. `go test ./...` 全绿
3. `go test -race` 核心包全绿
4. `go vet` / `gofmt` 干净
5. 路由 100% 覆盖（对比 Python 78 条）
6. 无死代码（定义了但无调用点的导出符号）
7. 无未接线配置（config 有访问器但请求链路不读）
